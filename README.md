# aquilla-ambient

**Translate once, stay translated. Correct once, propagate.**

A research prototype for *ambient localization*: translation as a continuously
maintained transformation of content that lives where it already lives — a
folder, an InDesign file, a docs repo, an app's string files — instead of a
project you import into a translation management system.

This is the sibling repo for testing the plan in [docs/SPEC.md](docs/SPEC.md).
It is deliberately standalone: no Aquilla app, database or Worker dependency
(spec §7, Phase 1).

```
 drop files in a folder ──► translations/<lang>/… appear and stay in sync
 edit a translation in InDesign / any editor ──► it becomes a human decision
 change the English ──► only what changed is retranslated; human work survives
 add a glossary term ──► only paragraphs that contain it are retranslated
 fix a word once ──► accept the suggestion, it spreads to every machine translation
 ask for Swahili ──► any file, any language, on demand (CLI, URL, WebDAV, agent)
```

## Try it (two minutes, no API key)

```bash
pnpm i
pnpm demo          # narrated walkthrough in ./demo-workspace
pnpm test          # 121 tests, incl. property-based convergence tests
pnpm gate          # measures the spec's Gate A and writes docs/GATE-A.md
```

Use your own folder:

```bash
pnpm ambient init ~/Desktop/multilingual --source en --targets fr,es
cp brochure.idml ~/Desktop/multilingual/
pnpm ambient watch ~/Desktop/multilingual      # keeps translations/ in sync
pnpm ambient serve ~/Desktop/multilingual      # inspector UI + "any language" drive
```

Real translation uses Claude: set `"translator": "claude"` in `ambient.json`
and `ANTHROPIC_API_KEY`. The default `pseudo` translator is deterministic
pseudo-localisation (accents + realistic text expansion) so everything —
including layout overflow — can be tested offline.

## How it works

```
 External sources      IDML · Markdown · JSON strings   (folder today; Drive/Git/CMS next)
        │  adapters: extract → units with native scopes/anchors; render by surgical patch
        ▼
 Functional core       reconcile identities · plan · patch (preconditions + authority)
        │              — format-agnostic; the same code serves all three formats
        ▼
 Localization engine   context (terms, rules, corrections) · translate · validate · layout
        │
        ▼
 Durable facts         append-only ledger: observations, proposals, human edits,
                       approvals, decisions, publishes, conflicts  (+ published bytes)
        │
        ▼
 Surfaces              watched folder · CLI · inspector UI · WebDAV drive · MCP agent tools
```

Key properties, each enforced in code and tested:

- **The customer's files stay the system of record.** `.ambient/` holds only
  facts, decisions and the bytes we published (needed for 3-way merges and
  rollback).
- **Native artifact preservation.** IDML output is produced by replacing the
  bytes of text slots only; every other ZIP member is copied as the original
  compressed record. Unchanged input → byte-identical output.
- **Identity, not hashes.** Paragraphs keep their identity through edits,
  moves, splits and merges; anything uncertain is escalated as *ambiguous*,
  never guessed (`src/core/reconcile.ts`).
- **Human authority.** Agent output never replaces human or approved text
  for the same source — not by timestamp, not by arrival order. When the
  source changes under a human translation, the policy is either *revise*
  (the model edits the human text, flagged for review) or *hold*.
- **Convergence.** Facts are de-duplicated and folded in hybrid-logical-clock
  order, so replicas that exchange ledgers agree; concurrent human edits are
  detected and surfaced, because convergence is not agreement.
- **Bidirectional feedback.** Edits made in the translated file are
  recovered by diffing against the bytes we published, recorded as human
  decisions, and mined for reusable corrections.

Details: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Surfaces

| Surface | What it is for |
|---|---|
| Watched folder (`ambient watch`) | The default: drop files, get languages. Edit translations in place. |
| CLI (`ambient …`) | `sync`, `open --in <lang>`, `explain`, `approve`, `edit`, `term`, `rule`, `correction`, `resolve`, `history`, `rollback` |
| Inspector (`ambient serve`) | Review/edit/approve in a browser; conflicts and suggestions; report |
| WebDAV drive (`/dav/`) | Mount in Finder/Explorer; `/dav/<any-lang>/file` is translated when opened |
| MCP (`ambient mcp`) | Lets Claude (Desktop/Code) inspect and steer the folder in conversation; `ambient_view` generates a focused review page on demand |

Add to Claude Code: `claude mcp add ambient -- pnpm --silent --dir /path/to/aquilla-ambient ambient mcp /path/to/folder`.

## Repository map

```
src/core/        types, tagged text, similarity, reconcile, ledger, context, plan, patch
src/adapters/    zip, xml (offset-preserving), idml/, markdown/, json/, registry
src/engine/      pipeline (the sync loop), translator (pseudo + Claude), feedback, report
src/ambient/     workspace (folder + ledger IO), cli, ops, server (+inspector), mcp
src/fixtures/    synthetic IDML builder
test/            unit, property-based and end-to-end lifecycle tests
scripts/         demo.ts, gate-a.ts
fixtures/        CC0 feature-rich IDML (from aquilla) + real InDesign exports (SimpleIDML, BSD)
docs/            SPEC, ARCHITECTURE, GATE-A (generated), RESEARCH-PLAN, LAYOUT
```

## Not done yet (on purpose or not)

- No InDesign in the loop: integrity and overset are proxies (docs/LAYOUT.md).
- The Claude translator is implemented with structured output and tag
  validation but was not exercised against the live API in this session.
- InDesign `AppliedLanguage` (hyphenation/spelling language) is not yet set
  on translated text.
- Tracked changes (`<Change>`) and literal text inside unknown elements are
  preserved but not translated, and reported.
- Local only: no auth, no hosted service, no Drive/Git connectors yet.
