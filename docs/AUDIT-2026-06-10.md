# codex-web-app — Engineering Audit & Improvement Plan

_Date: 2026-06-10 · Scope: full repository, analysis only (no code changed) · Method: 7 parallel deep-dive passes over architecture, code quality, testing, performance, dependencies/DevEx, documentation, concurrency, and caching/resilience._

> **Security is tracked in a separate document** (`docs/SECURITY-NOTES-2026-06-10.md`) and is intentionally omitted here. This document covers everything else.

## 1. Executive Summary

**Overall health: C+ (high variance).** This is an unusually ambitious 8-week-old prototype (1,730 commits since 2026-04-13, single primary author) that already deploys to production and is aimed at a credibility-critical audience (SIL/UBS Paratext translation consultants). In places the engineering is senior-grade: a durable IndexedDB outbox with quarantine semantics, the FRO-247 write-clock fencing that correctly defends local edits against stale read-backs, a lint-enforced event-authorization perimeter, a D1→Postgres shim that let a full datastore migration ship without touching ~80 routes, and ~350 test files. But three Critical issues sit directly on the product's core promise — trustworthy collaborative translation — and they pull the grade down hard.

**Top 3 risks:**
1. **The event log silently corrupts under ordinary two-user concurrency** ([sync-worker/src/events/handlers/cell-events.ts:60](sync-worker/src/events/handlers/cell-events.ts)). `MAX(server_seq)+1` computed inside each transaction plus an unqualified `ON CONFLICT DO NOTHING` means a concurrent commit's event-log row is silently dropped while its projection still commits — `cells.event_id` then points at a non-existent event, and a rebuild reverts the edit. This is the normal collaboration case, and it corrupts the single source of truth.
2. **The safety net is currently down.** The root `package-lock.json` is out of sync with `package.json`, so `npm ci` hard-fails and all four GitHub workflows have likely been red for ~a week. CI is not gating anything right now; prod ships only from a developer laptop.
3. **The app has no crash visibility.** No React error boundary, no `window.onerror`/`unhandledrejection`, no exception telemetry — a render throw or a stale lazy-chunk after redeploy is a permanent white screen that no one is ever notified about.

**Top 3 opportunities:**
1. **Serialize chain-mutating writes per project** (a per-project Postgres sequence or a partial unique index + CAS) — one change closes the Critical event-log corruption (F-RACE-1), the live/replay divergence (F-RACE-2), and the concurrent-batch 500 retry storms (F-PERF/seq) at once.
2. **Build the `?since=` delta read the cache was designed for** — kills ~98% of cell-read volume (today opening one Bible book = ~1.8–3.6M Postgres row reads across ~60 full-file re-reads, repeated on every window focus).
3. **Make CI authoritative again** — pick pnpm as canonical, switch the four workflows to `pnpm install --frozen-lockfile`, and add the gates that exist locally but run nowhere in CI (lint, unit, the sync-worker test suite, e2e). This un-breaks deploys and converts a large pile of already-written tests into a real net.

The decomposition story is healthy outside two god files (`ProjectWorkspace.tsx` ~3,000 lines / 197 hook calls, `EditorRow` ~1,944 lines / ~45 props), and the data layer is strict-clean today (passes `tsc --strict` with zero errors — just unenforced). The fix list is mostly surgical, not a rewrite.

## 2. Repo Map

**Purpose.** Aquilla — a browser-first (and Tauri desktop) collaborative Bible-translation workspace. Bilingual experts translate scripture cell-by-cell (source ↔ target), with AI completion, terminology management, audio/oral translation, back-translation, comments, and org-level oversight for managers/owners who don't read the target language. First users are Paratext consultants, so USFM/Paratext import-export fidelity is make-or-break.

**Stack.** React 19 + Vite 8 SPA (TypeScript), Tailwind 4 + shadcn/base-ui, TanStack Virtual, TipTap editor. Three Cloudflare Workers: `auth-worker/` (identity/permissions, Hono), `sync-worker/` (event log + projection writer), `worker/` (48-line edge router selecting marketing vs app HTML). Neon Postgres via Hyperdrive is the live datastore (migrated off D1); R2 for media blobs; a per-project `ProjectSync` Durable Object for presence/focus-locks/broadcast (no durable state). Client persistence is IndexedDB (outbox + cells cache). Multi-brand build (`BRAND=aquilla|codex|honeycomb|context`).

**Architecture in one paragraph.** Event-sourced CQRS. The editor commits a cell → an event is enqueued in a durable IndexedDB outbox → an app-shell-owned flusher mints a per-file JWT and POSTs ≤100 events to `sync-worker` `/events` → the worker authorizes each event, runs idempotency/AD-2 guards, and projects into the `cells`/`files` tables inside one Postgres transaction → it fans out `event.applied` to the project's DO → WebSocket broadcast → clients revalidate the affected cell. The event log is the source of truth; projections are rebuildable.

## 3. Audit Report

Findings are grouped by dimension and sorted by severity. Each carries file:line evidence, a concrete consequence, and a **FACT** (verified in code) vs **JUDGMENT** (reasoned inference) label. IDs are stable for the task plan.

### 3.1 Concurrency & Race Conditions
_The highest-severity cluster. The root cause is structural: guards (sequence allocation, first-child check) are evaluated **outside** the transaction that commits the writes._

> **Resolved design intent (owner, 2026-06-10):** focus-locks are the *primary* mechanism — they exist to keep two **live** users from editing the same cell at once; the FWW/AD-2 conflict resolution is the *fallback* only for **offline** users who couldn't see another user's presence/lock. Expected scale is a few cooperative concurrent users who generally stay out of each other's way (different cells/files).
>
> **Critical caveat this intent does *not* cover:** RACE-1 is **project-scoped, not cell-scoped**. The `server_seq` collision fires for *any* two concurrent commits in the same project — including the exact "staying out of each other's way on different cells/files" workflow that the intent treats as safe. Focus-locks (per-cell) and user cooperation therefore provide **zero** mitigation for RACE-1. Likewise, two offline users returning and flushing concurrently hit RACE-1 *and* RACE-2 — i.e. the bugs bite hardest in precisely the offline-conflict scenario that FWW is meant to handle. Net effect of the clarification: it confirms RACE-1 stays Critical, raises the stakes on making FWW actually work (RACE-2) and on lock *reliability* (RACE-6), but it does **not** require hard server-side lease enforcement (RACE-5) — advisory locks are acceptable for cooperative few-user editing *provided they are reliable*.

**RACE-1 — [CRITICAL] [FACT] Concurrent commits to one project silently drop event-log rows.**
`INSERT ... SELECT COALESCE((SELECT MAX(server_seq) ...),0)+1 ... ON CONFLICT DO NOTHING` ([cell-events.ts:60](sync-worker/src/events/handlers/cell-events.ts), identical in [import-route.ts:111](sync-worker/src/events/import-route.ts)) with unique index `idx_events_project_seq` ([schema.sql:431](db/postgres/schema.sql)). Two concurrent `POST /events` for the same project compute the same `N+1` under READ COMMITTED; the loser's unique-index collision is swallowed by the unqualified `ON CONFLICT DO NOTHING` (matches *any* unique violation, not just the `id` PK), but its `cells` UPSERT and counter updates still commit, and the client gets `accepted`. **Consequence:** `cells.event_id` references an event that doesn't exist in the log; per-cell history loses the edit; `rebuild.ts` reverts the cell; the next commit chains `parentId` to a ghost. This fires under normal two-user editing and corrupts the source of truth. Snapshot restore's INSERT ([snapshots-route.ts:236](sync-worker/src/events/snapshots-route.ts)) has *no* `ON CONFLICT` at all → a seq collision aborts the restore mid-flight with a 500.

**RACE-2 — [HIGH] [FACT] AD-2 "first child wins" guard is a TOCTOU; concurrent siblings both win, neither flagged stale.**
`isWinningChild()` is a plain SELECT run before any insert ([route.ts:281](sync-worker/src/events/route.ts) → [event-projection.ts:988](sync-worker/src/events/event-projection.ts)); the projection UPSERT is unconditional LWW. Two users branching the same chain head both pass the guard, both commit, last-tx-to-commit wins by undefined order, and **no `stale` entry is returned** so neither client shows the "your edit was bumped" banner the whole stale-sibling pipeline was built for. Worse: a later `rebuild.ts` applies the guard in `server_seq` order and picks the *first* sibling, so replayed state disagrees with live state. **Consequence:** silent lost update + live/replay divergence — exactly what the strict AD-2 rework was meant to prevent; it now only catches temporally separated (offline) conflicts.

**RACE-3 — [HIGH] [FACT] Client chains `parentId` from the projection row, not its own pending event → self-reverting typing.**
`parentId: cell.targetEventId ?? cell.sourceEventId ?? null` ([EditorTable.tsx:1723](src/components/EditorTable.tsx); same at [ProjectWorkspace.tsx:1072](src/components/ProjectWorkspace.tsx)). The component already maintains `pendingTargetEventIdRef` but uses it only for validations. A second idle-commit (1.2s debounce) that fires before the read-back lands chains to the *old* parent, becoming a sibling of the user's own earlier event — which the server then dead-letters. **Consequence:** the user's continued typing loses to their own earlier keystrokes; they get a "changes rejected, newer edits won" banner where the "winner" is older text. **This is the cheapest high-value fix in the audit** — chain `parentId` through the ref that already exists.

**RACE-4 — [MEDIUM] [FACT] No-Web-Locks fallback flusher has no reentrancy guard → concurrent double-POST.**
When `navigator.locks` is unavailable (plain-HTTP LAN, some webviews), the flusher is `setInterval(() => void tick(), 5000)` with no in-flight guard ([useOutboxFlusher.ts:145](src/hooks/useOutboxFlusher.ts)). A flush slower than 5s overlaps; both ticks `peek` and double-POST the same events; the server dedup SELECT is outside the tx so both pass, and the projection re-runs `validated=0, endorsement_count=0` ([event-projection.ts:296](sync-worker/src/events/event-projection.ts)) — wiping a validation that landed between the two applies. The primary (Web Locks) path is correctly defended.

**RACE-5 — [MEDIUM] [FACT] Focus-lock leases are advisory; never checked on the write path.** Locks live only in DO memory; `grep` over `/events` finds zero lease references. Enforcement is client-only ([EditorTable.tsx:1708](src/components/EditorTable.tsx)) and races the very broadcasts it depends on. The UI presents locks as protection they don't provide. **Resolved (2026-06-10):** advisory-only is the accepted design for the cooperative few-user case — hard server-side lease enforcement is *not* required. But because locks are now confirmed to be the *primary* concurrency mechanism (not a hint), they must be **reliable** in the common case: close the client-side claim/broadcast race window (so a commit can't slip through the gap between another user's `focus.claim` and the `lock.claimed` render) and fix RACE-6, which silently breaks locks even for cooperative users.

**RACE-6 — [MEDIUM] [FACT] Same user, two tabs: closing one releases the other tab's locks/presence.** `applyDisconnect` releases *all* of a `userId`'s locks without checking for other live connections ([project-do.ts:213](sync-worker/src/project-do.ts) → [project-do-handlers.ts:242](sync-worker/src/project-do-handlers.ts)). Opens an overwrite window on a cell the UI says is locked.

**RACE-7 — [MEDIUM] [FACT] Invite acceptance is check-then-act with no transaction.** Five auto-commit statements, used-stamp UPDATE has no `AND used_at IS NULL` guard ([invites.ts:213](auth-worker/src/routes/invites.ts)). Two users with a forwarded single-use link both get admitted; the same user double-clicking gets a 500 despite success.

**RACE-8 — [MEDIUM] [FACT] Quarantine breaks per-cell ordering → dangling parent pointers.** A dead-lettered parent event (5-attempt cap, burned even by pure network errors over ~2.5min of flaky connectivity) lets its child flush alone; `isWinningChild` never verifies the parent exists, so the child projects with a dangling `parentId` ([outbox.ts:278](src/lib/sync/outbox.ts), [outbox-flush.ts:159](src/lib/sync/outbox-flush.ts)). Breaks history walks and rebuild. (Tightly coupled to RES-2.)

**RACE-9/10 — [LOW]** Counter recompute can transiently miss a concurrent commit under EvalPlanQual (self-heals next event); sync-token mint has no single-flight (wasted requests only). There is **no session-JWT refresh mechanism at all**, so the classic refresh-rotation race doesn't exist.

**Defended (verified negative results worth preserving):** single-drainer Web Lock; lost-response retry idempotency (same UUIDv7 + server dedup + `ON CONFLICT`); FRO-247 stale-fetch fencing (thorough, and applied at *every* cell writer — editor, completions, history restore, replace-all, terminology); focused editors never re-hydrated by remote broadcasts ([TranslatedEditor.tsx:267](src/components/TranslatedEditor.tsx)); snapshot restore's CAS `WHERE event_id = <head>` ([snapshots-route.ts:262](sync-worker/src/events/snapshots-route.ts)) — the one true compare-and-swap in the codebase; DO single-threaded per instance.

**E2E gap:** `e2e/specs/collab/` has six specs but all are *sequential* propagation ("alice writes, bob sees within 15s"); `concurrent-edit.smoke.spec.ts` never makes two users write concurrently. None of RACE-1..8 has test coverage.

### 3.2 Performance

**PERF-1 — [CRITICAL] [FACT/JUDGMENT] `GET /cells` re-reads the entire file per page request.** The route pulls every row for the file, chain-walks the full set in memory, then slices the requested page ([cells-read-route.ts:258](sync-worker/src/events/cells-read-route.ts), unbounded SELECT at `:297`, slice at `:332`). A 30k-cell book streamed in ~60 pages = **~1.8–3.6M row reads + 60 full sorts per open**, ~60× necessary. Dominant server read cost for the product's core artifact.

**PERF-2 — [HIGH] [FACT] `POST /events` runs 1–3 serial pre-check queries per event (N+1).** Per event: idempotency SELECT, `isWinningChild` SELECT, stale-source SELECT per commit, and `project_settings` SELECT per validate/harmonize — none cached across the batch ([route.ts:194-542](sync-worker/src/events/route.ts)). A 100-event flush = ~200–300 serial Hyperdrive round-trips before the batch commits (~0.5–1.5s pure latency). Settings could be read once/request; idempotency batched into one `WHERE id IN (...)`.

**PERF-3 — [HIGH] [FACT] Full file-counter recompute (5 aggregate subqueries) appended per event.** `fileCountersRecomputeStmt` re-derives 5 aggregates over all of a file's cells on every cell-mutating event ([event-projection.ts:96](sync-worker/src/events/event-projection.ts)); the interactive path never defers. 100 commits on one book = 100 full-file aggregate scans inside one transaction, serialized on the `files` row lock. The bulk-import path already does this right (`deferFileCounters` + one recompute). Coalesce to once per (file, batch) — order-of-magnitude cut, zero semantic change.

**PERF-4 — [HIGH] [FACT] Client re-streams the whole file on every window focus / visibility change.** `useCells` has no viewport windowing and re-streams on `focus` + `visibilitychange` + post-commit ([useCells.ts:617](src/hooks/useCells.ts), `:719`), contradicting the app-wide `refetchOnWindowFocus: false`. Alt-tabbing back to a book = ~60 HTTP requests, each triggering PERF-1's full re-read. (= caching CACHE-2/CACHE-4.)

**PERF-5 — [MEDIUM] [FACT] `server_seq = MAX+1` serializes writers and 500s concurrent batches.** Two concurrent same-project requests collide on the unique index; the whole 100-event chunk transaction fails with a 500, the client retries (burning its 5-attempt budget) ([cell-events.ts:62](sync-worker/src/events/handlers/cell-events.ts), [route.ts:587](sync-worker/src/events/route.ts)). Effective single-writer-per-project — the thing the Neon migration was meant to relieve. (Same root cause as RACE-1; fixed by the same move.)

**PERF-6 — [MEDIUM] [FACT] `rebuildFromCache` rebuilds every CellData on every page/outbox tick/stats change** ([useCells.ts:392](src/hooks/useCells.ts)) — O(pages × N) ≈ ~1M `buildCellData` calls per book open, plus a fresh `peekOutboxBatch(2000)` IDB cursor walk per outbox notification. Mints new object identities for all 30k cells, forcing all visible rows to re-render.

**PERF-7 — [MEDIUM] [FACT] O(N)-over-all-cells derivations re-run whenever the cells array identity changes** (`cellsWithAudio`, `displayCells`, `sectionByIndex` in EditorTable; `allProjectCells`, search-index rebuild in ProjectWorkspace). Stacked main-thread passes in the editing hot loop (mitigated, not removed, by React Compiler).

**PERF-8 — [MEDIUM] [FACT] Per-event DO fan-out ≈ 2 subrequests per committed event** ([route.ts:644](sync-worker/src/events/route.ts), [broadcast.ts:53](sync-worker/src/events/broadcast.ts)). A 100-event batch ≈ 200 subrequests against Cloudflare's 1,000/invocation cap. Batch into one `__broadcast` body per project.

**PERF-9 — [MEDIUM] [FACT] Unbounded growth.** No compaction/GC of the `events` table (append-only by design, but history/rebuild/storage scale with it forever; snapshots are labels only); client cells cache stores full row snapshots per (project,file) with no TTL/LRU and `deleteCellsCache` has zero callers; quarantined outbox records persist indefinitely ([cells-cache.ts](src/lib/sync/cells-cache.ts), [outbox.ts:40](src/lib/sync/outbox.ts)).

**PERF-strengths:** virtualization is genuinely effective (only `getVirtualItems()` renders; stable handler refs); the outbox flusher is well-engineered (Web Locks, 5s→60s backoff, batch-of-100, quarantine); **AI inference is off the main thread** in lazy `?worker` modules so the ~58MB WASM never ships in the page; bulk import does counters right; Postgres FTS via a generated `value_tsv` GIN column replaced the old FTS5 shadow-table writes.

### 3.3 Caching & Resilience

**RES-1 (CACHE-1/2) — [CRITICAL/HIGH] [FACT] No HTTP cache semantics + the `?since=` delta endpoint was never built.** No `Cache-Control`/`ETag`/conditional-GET on any hot worker read; the only cache headers are anti-caching. `cells-cache.ts:10` explicitly says "Phase 2 will add a `?since=lastEditAt` endpoint" and already stores `maxLastEditAt` — Phase 2 never shipped, so every open is a full re-stream. **Opportunity:** emit `ETag: "<fileId>:<maxServerSeq>"`, answer `If-None-Match` with a 304 from one cheap `MAX(server_seq)` query; build the `?since=` cursor and merge into IDB. Removes ~98% of cell-read volume and makes the focus-refetch (PERF-4) nearly free.

**RES-2 — [HIGH] [FACT] Edits permanently stop syncing after a ~3–5min outage.** `OUTBOX_MAX_ATTEMPTS=5`; status-0 and 5xx both burn the budget; `failed` records are skipped forever and only recover via the inspector's manual Retry ([outbox.ts:24](src/lib/sync/outbox.ts), [outbox-flush.ts:190](src/lib/sync/outbox-flush.ts)). Token-mint failures correctly *don't* burn the budget — apply that same policy to transient POST failures, or auto-requeue `failed` on `online`/`authEpoch`.

**RES-3 (R4) — [CRITICAL] [FACT] No error boundary, no global error hooks, no crash reporting.** Zero `ErrorBoundary`/`componentDidCatch`/`window.onerror`/`unhandledrejection`/router `errorElement` in `src/`; PostHog is pageview-only ([posthog.ts:8](src/lib/posthog.ts)). A render throw or a stale lazy-chunk 404 after redeploy = permanent white screen, unreported. Lowest-cost/highest-blindspot item in the whole audit.

**RES-4 (R3) — [MEDIUM] [FACT] Optimistic UI is applied before the durable enqueue, and enqueue failure is swallowed.** `onOptimisticEdit(...)` runs, then `void emitTargetCellCommit(...).catch(err => console.warn(...))` ([EditorTable.tsx:1714](src/components/EditorTable.tsx)). If the IDB put throws (quota, private mode), the cell shows "saved" styling while the event exists nowhere durable → silent loss on tab close. The `InsufficientRoleError` that `events-emit.ts` claims callers "surface to the user" also dies in this `console.warn`.

**RES-5 (R5) — [HIGH] [FACT] Backend outage renders as "you have no projects / not found".** `fetchAccessibleProjects` returns `[]` on any non-2xx/network error ([cloud-projects.ts:74](src/lib/cloud-projects.ts)); `useProject` maps a null to `"not-found"`. The justifying comment ("so Dashboard can render local state when offline") is stale — the thin-client refactor removed the local fallback. Users conclude their data was deleted. Distinguish `{ok:false}` from empty.

**RES-6 (R7) — [MEDIUM] [FACT] No timeout/AbortController on the critical read & flush paths.** Neither `cells-read.ts`, the `/events` POST, nor sync-token mint passes a signal/timeout. A hung connection strands the skeleton (soft refetches are dropped while `inFlightRef` is true) until the browser's multi-minute socket timeout. The pattern exists in-repo (bulk-import, branching-search accept signals) — apply `AbortSignal.timeout(15_000)`.

**CACHE-3 — [MEDIUM] [FACT] react-query is configured but ~97% of fetching bypasses it.** Only 3 files use `useQuery`/`useMutation`; `useProject`, file lists, members, comments, settings are all raw fetch with no dedup/cross-component cache. Two components needing the same file list issue two calls.

**CACHE-5 — [MEDIUM-HIGH for audio projects] [FACT] Audio bytes re-downloaded on every remount.** Bytes cached in a per-component ref only; server forbids HTTP caching and the request is authed so the browser cache can't help ([useCellAudio.ts:158](src/hooks/useCellAudio.ts), [audio.ts:156](sync-worker/src/audio.ts)). Audio is immutable (new recording = new `audioId`) → cache by `audioId` with `immutable` semantics + LRU. Biggest win for the oral-translation persona.

**RES/CACHE strengths:** the outbox is "the best-engineered subsystem in the app" (durable-at-enqueue, so tab-close loses nothing; quarantine prevents head-of-line wedge); ML model weights *are* cached forever (Cache API); the branching-search KV cache is textbook (keyed by `corpus_event_max + query-hash`, self-invalidating); the IDB cells snapshot paints <50ms; FRO-247 fencing and token-null backoff are rigorous; R8 — the sync-status indicator hardcodes "live" when online, conflicting with the outbox indicator (Low).

### 3.4 Architecture & Design

**ARCH-1 — [HIGH] [FACT] `ProjectWorkspace` is one ~3,000-line function with 197 hook calls** (46 useState, 26 useEffect, 28 useMemo, 42 useCallback, 17 useRef; 123 imports) owning tabs, editing, completion, audio/TTS/diarization, video, comments/history/rules drawers, chat, search, sharing, terminology, assignments, lifecycle ([ProjectWorkspace.tsx:192](src/components/ProjectWorkspace.tsx)). Every feature change risks every other; it's the merge-conflict epicenter for the swarm workflow. The ~30 custom hooks are already clean seams — the monolith is the *wiring*, so the split is mechanical, not a rewrite.

**ARCH-2 — [HIGH] [FACT] `EditorTable` exposes ~50 props and a 1,944-line `EditorRow`.** `EditorTableProps` has 51 props ([EditorTable.tsx:335](src/components/EditorTable.tsx)); `EditorRow` spans 1565–3508 rendering text/audio/BT/interlinear/terms/violations/validation/selection/history. `React.memo` over ~45 props is fragile (the file already ships `window.__perfRowRenders` instrumentation). ~15 leaf components are already extracted — the row body just never got the same treatment.

**ARCH-3 (= QUAL-9) — [HIGH] [FACT] Shared contracts are hand-mirrored and have already drifted.** `SyncTokenClaims` is defined twice — `username` required in the minter ([auth-worker/src/types.ts:117](auth-worker/src/types.ts)) vs optional in the verifier ([sync-worker/src/auth.ts:7](sync-worker/src/auth.ts)); role constants are triplicated with no compile-time link; the event grammar is a 331-line "client mirror" with a comment asking humans to "keep field names aligned." The drift is the proof the mechanism leaks. The `packages/data-model/` dir that should hold this exists but is empty.

**ARCH-4 — [MEDIUM] [FACT] Chain-mutating classification is a deny-list in one place, an allow-list in another.** `route.ts:248` uses a 16-entry negative list; `event-projection.ts:959` uses an 8-entry positive `CHAIN_MUTATING_KINDS`. A new non-chain event kind not added to the deny-list is treated as chain-mutating by default and silently dropped as a "stale sibling." Default-unsafe; collapse to one exported predicate.

**ARCH-5 — [MEDIUM] [FACT] sync-worker routing is a ~35-handler sequential waterfall** ([index.ts:156](sync-worker/src/index.ts)) with implicit precedence (the file warns "`/search/passages` must be checked BEFORE `/search`"), while auth-worker uses Hono. Two routing idioms; route additions require knowing global order. Every handler already has the `(req, env) → Response|null` shape, so converging on Hono is low-risk.

**ARCH-6 — [LOW] [FACT] Dead directories + minor layering inversions.** `cors-proxy/` and `packages/*` are empty husks; `src/lib/migrate/` is one-shot tooling in the app tree; `src/lib/frontier/` is misleadingly named (now wraps in-repo auth). 6 minor `lib→components` / `hooks→components` type-only imports anchor lib to components and block future extraction. Otherwise layering is clean (zero runtime lib→component imports across 30+ subdirs).

**ARCH-strengths:** durable/honest offline write path; the 179-line datastore shim (migration insurance); DO discipline (transient state only — no DO-storage migration debt ever); the edge entry-point split; rebuildable projections.

## 4. Improvement Strategy

Five themes explain the bulk of the findings.

**Theme A — Guards live outside the transaction they protect.** _Target state:_ all conflict arbitration (sequence allocation, first-child) is enforced atomically with the write — a per-project Postgres sequence (or seq allocation in the DO) plus a partial unique index on `(project_id, file_id, cell_id, parent_id)` for chain-mutating kinds and/or a CAS `WHERE event_id = parent` on the cells UPSERT. _Principle:_ correctness invariants must be enforced by the database, not by check-then-act in application code. _Covers:_ RACE-1, RACE-2, RACE-3 (client side), PERF-5.

**Theme B — The safety net runs nowhere authoritative.** _Target state:_ CI is green and is the merge/deploy gate — one package manager (pnpm), `--frozen-lockfile`, lint + unit + both worker suites on every PR, the full e2e suite on a schedule/PR job, a true <2min smoke subset on pre-push, and deploys gated on CI. _Principle:_ CI must be authoritative; local hooks are a convenience, not the gate. _Covers:_ DEPS-1/2/3, TEST-1/2/3/6/7, DEVEX-1.

**Theme C — The core read/write loop is O(file) where it should be O(change).** _Target state:_ reads are delta-based (`?since=` + ETag/304, IDB merge) and writes amortize per-batch work (counters once per file/batch, settings/idempotency cached/batched per request, DO fan-out batched). _Principle:_ pay for what changed, not for the whole artifact, on the product's hot path. _Covers:_ PERF-1/2/3/4/8, RES-1, CACHE-3/5, PERF-9 (partially).

**Theme D — Failures are invisible or mislabeled.** _Target state:_ a top-level error boundary + `unhandledrejection`/chunk-load handling wired to exception telemetry; backend-unreachable distinguished from empty/not-found; transient outbox failures don't permanently park edits; timeouts on critical fetches; worker observability on. _Principle:_ every failure is either recovered or surfaced — never silently swallowed or mislabeled as "no data." _Covers:_ RES-2/3/5/6, RACE-8 (partially), DEVEX-2, QUAL-5.

**Theme E — Contracts and big components are held together by discipline, not tooling.** _Target state:_ `tsconfig.app` strict; shared types (event grammar, roles, token claims) in `packages/data-model` consumed by all tiers; the two god files split along their existing comment-delimited seams; dead dirs deleted; the docs agents read corrected. _Principle:_ make the compiler and the directory structure enforce what comments currently ask humans to remember. _Covers:_ QUAL-1/2/3, ARCH-1/2/3/4/6, DOCS-1/2/3/4, DEPS-4.

**Explicit non-goals (recommend NOT fixing now, with rationale):**
- **Event-log compaction/snapshotting (PERF-9 server side).** Append-only is correct for an event-sourced system; storage cost is trivial at current scale. Revisit only when a single project's log measurably slows rebuild — not before. Effort/payoff is poor today.
- **Rewriting sync-worker routing to Hono (ARCH-5).** Real but low-impact; do it opportunistically when next touching the router, not as dedicated work.
- **Full react-query migration of all 50+ hooks (QUAL-3/CACHE-3).** Migrate only the plain reads that benefit from dedup (project, files, members); leave `useCells`' bespoke protocol alone — its offline/clock-fence semantics are load-bearing and well-tested.
- **Cross-browser / Tauri e2e.** Out of scope per AGENTS.md; Chromium-only is the right call for a prototype.
- **Audio Range/streaming (CACHE-6), eBible mirror (CACHE-7), sync-token single-flight (RACE-10).** Low-frequency; defer.

**Definition of done (measurable signals):**
- Zero Critical findings (RACE-1, PERF-1, RES-3, DEPS-1 resolved and regression-tested).
- A concurrent-edit e2e test (two users write the same cell simultaneously) passes and would fail against today's `main`.
- CI is green and required: `pnpm install --frozen-lockfile` succeeds; lint + unit + both worker suites + a <2min smoke run on every PR; deploys blocked on CI.
- Opening a 30k-cell file is one `?since=`/304-eligible request on a warm cache, not ~60 full re-reads; window-focus does not re-stream.
- A forced render error shows a recovery UI and emits one exception event; a 5xx from the backend shows "can't reach server," not "no projects."
- `tsconfig.app.json` has `"strict": true` and the build is green.

### Top-3 implementation sketches

**M1-1 — Serialize per-project writes (the Critical fix).**
_Approach:_ Replace the inline `MAX(server_seq)+1` with a per-project monotonic allocator and make the log INSERT conflict-safe on the PK only. Two viable mechanisms: (a) a Postgres `SEQUENCE`-per-project (or a `project_seq_counters` row updated with `UPDATE ... RETURNING` inside the same tx — atomic, row-locked); or (b) allocate the seq inside the per-project DO (single-threaded) before the POST. Prefer (a) — keeps Postgres the single source of truth and avoids a DO round-trip on the write path.
_Key steps:_ (1) add the allocator; (2) change `ON CONFLICT DO NOTHING` → `ON CONFLICT (id) DO NOTHING` so only true idempotent replays are skipped, never seq collisions; (3) add a partial unique index on `(project_id, file_id, cell_id, parent_id) WHERE kind IN (chain-mutating)` and turn the `isWinningChild` check into an `INSERT ... ON CONFLICT DO NOTHING` whose row-count tells you if you won — atomic, inside the tx; (4) make the cells UPSERT a CAS (`WHERE event_id = <parent>`); (5) give `snapshots-route.ts` the same conflict-safety.
_Gotchas:_ READ COMMITTED won't save you — the fix must be a unique constraint or a row lock, not another SELECT. Must run against real Postgres (PGlite) under the M0-4 concurrent harness, not a mock. Coordinate with M2-1 (the `?since=` ETag keys on `maxServerSeq`, which this changes the allocation of). Verify `rebuild.ts` produces byte-identical projections before/after on a real project.

**QW-4 / RES-3 — Error boundary + telemetry.**
_Approach:_ A class `ErrorBoundary` at the App root (above the route `Suspense`) rendering a reload CTA; a `componentDidCatch` calling `posthog.captureException`; a module-level `window.addEventListener('unhandledrejection', …)`; and a chunk-load-error guard (catch `Failed to fetch dynamically imported module` → force one reload, guarded by a sessionStorage flag to avoid loops).
_Key steps:_ wrap `App.tsx:136`; add the global listeners in `main.tsx`; confirm PostHog is initialized before the listeners attach.
_Gotchas:_ the chunk-reload guard must not infinite-loop on a genuinely broken deploy; the boundary must not swallow the error in dev (re-throw when `import.meta.env.DEV`).

**M2-1 — `?since=` delta + ETag (the biggest perf win).**
_Approach:_ Server: on `/cells`, compute `maxServerSeq` for the file (one indexed query); set `ETag: "<fileId>:<maxServerSeq>"`; if `If-None-Match` matches, return 304. Add `?since=<seq>` → return only events/cells with `server_seq > since`. Client: store `maxServerSeq` in the IDB cache entry; on open, send `If-None-Match` (304 → use cache) or `?since=` (merge the delta into the cached rows); full stream only on cache miss or `file.rename`/rebuild signal.
_Key steps:_ extend `cells-read-route.ts`; add the merge to `cells-cache.ts`/`cells-read.ts`; gate the focus refetch (PERF-4) behind the conditional request.
_Gotchas:_ ordering — a delta merge must reconcile chain re-parents, not just append (reuse the existing chain-walk on the merged set); invalidation on rename/rebuild must bump the ETag; depends on M1-1 making `server_seq` allocation correct so the ETag is trustworthy.
