# Cleanup Post-Refactor

> **Status:** Pending — execute as the new architecture from [DATA_PERSISTENCE_PLAN.md](./DATA_PERSISTENCE_PLAN.md) reaches feature parity.
> **Last updated:** 2026-05-08
> **Pre-condition:** No production users. The app is in prototype phase, so cloud-side data can be deleted outright rather than migrated.

This document inventories the discrepancy between the *current* system (Y.Doc-as-truth, full-file Y.Doc snapshots in R2, per-file DOs holding Y.Doc in memory) and the *target* system (D1-as-truth, client SQLite-WASM replica, ephemeral Y.Text only for focused co-edit). It enumerates what to delete, what to migrate, and what to leave in place.

The companion architectural plan is at [DATA_PERSISTENCE_PLAN.md](./DATA_PERSISTENCE_PLAN.md). This doc is the *removal* counterpart — read both together when planning refactor execution.

---

## 1. Scope and ground rules

- **No users to protect.** Cloudflare-side data (R2 blobs, D1 rows) can be wiped. The reference data we need for testing can be re-generated by re-importing seed fixtures.
- **Code-side cleanup matters more than data-side.** Dead code that pretends to be load-bearing causes more harm than orphan bytes in R2.
- **One pass per area.** Do not stage half-deletions across PRs. When a code path is no longer reached, remove it whole — not behind a flag.
- **Tests are the proof.** A surface is safe to delete when no test depends on it and no production code path reaches it. Run the smoke suite (`npm run test:e2e:smoke`) after each removal.

---

## 2. What changes, at a glance

| Area | Today | Target |
|---|---|---|
| System of record for cells | Y.Doc serialized to R2 `snapshot.bin` + `tail/*.bin` | D1 `cells` table (with `cell_revisions` history) |
| Source text storage | Inside Y.Doc cell map (Phase 4f moves to D1) | D1 `cells.source_text` + `tag_dictionary` (Phase 4f complete + reshaped) |
| Hydration model | DO replays events into Y.Doc on cold load | Server-side snapshot rollup; client bulk-loads JSONL into local SQLite |
| Co-edit substrate | Persistent per-file Y.Doc held in DO RAM | Ephemeral per-cell Y.Text spun up only when ≥2 clients focus the same cell |
| Client local store | Y.IndexedDB + scattered React Query caches | SQLite-WASM (OPFS) + outbox table + FTS5 |
| Project ↔ source binding | Implicit (project owns its files) | Explicit: project pinned to `library_documents.id` + `library_document_versions.id` |
| Cell address | Implicit ordinal in Y.Doc | Stable semantic address from format adapter |
| Inline formatting | Y.XmlFragment with marks (Milestone 9 path) | Plain TEXT + placeholder tokens + per-cell `tag_dictionary` |
| Share-link bootstrap | Legacy `signaling/` worker | Same sync token flow as authenticated users |

## 3. R2 cleanup

### 3.1 Delete outright

These keys exist only because of the Y.Doc-as-truth architecture. The new system never reads or writes them.

```
projects/{projectId}/files/{fileId}/snapshot.bin
projects/{projectId}/files/{fileId}/tail/*.bin
projects/{projectId}/files/{fileId}/checkpoints/*.bin
```

**Procedure.** Use `wrangler r2 object delete` or the admin endpoint on `codex-sync-worker` (which already has a cleanup hook — see [SYNC.md §"Open follow-ups"](./SYNC.md)).

```sh
# Dry-run an inventory first.
wrangler r2 object list <bucket> --prefix "projects/" > /tmp/legacy-keys.txt
wc -l /tmp/legacy-keys.txt
# Spot-check a sample, then delete.
xargs -a /tmp/legacy-keys.txt -I {} wrangler r2 object delete <bucket> {}
```

Acceptable alternative: leave the bytes in R2 (they cost nothing meaningful at this scale) and ensure no code path reads them. Either is fine; the prompt is to pick one and act.

### 3.2 Keep / extend

These prefixes do not exist yet in the current architecture but will be introduced. No cleanup action — listing here so the R2 layout is unambiguous.

```
sources/{org_id}/{library_doc_id}/{source_hash}
skeletons/{org_id}/{library_doc_id}/{skeleton_hash}
snapshots/{project_id}/{seq}.jsonl.gz
exports/{project_id}/{export_id}/{filename}
clips/{project_id}/source/{cell_id}.{ext}
clips/{project_id}/generated/{cell_id}/{revision}.{ext}
```

### 3.3 Audio assets

`MMS_R2_HOSTING.md` describes a separate audio-hosting story. Unaffected — leave its keys and code path alone.

## 4. D1 cleanup

### 4.1 `frontier-db-v2` (identity + permissions)

No cleanup required. Tables (`users`, `organizations`, `roles`, `projects`, `project_members`, `project_invites`, etc.) carry forward.

The new architecture *adds* tables in this same database: `library_documents`, `library_document_versions`, `cell_revisions`, `commits`, `speakers`, `cell_media`, `term_entries`, `cell_comments`, `cell_qa`, plus columns on `projects` (`library_doc_id`, `bound_version_id`, `source_lang`, `target_lang`, `sync_seq`, `snapshot_seq`, `snapshot_key`).

### 4.2 `codex-db` (CQRS read model)

Today's tables and their fate:

| Table | Action | Notes |
|---|---|---|
| `events` | **Keep + extend.** | Add new event kinds per [DATA_PERSISTENCE_PLAN.md §4.6](./DATA_PERSISTENCE_PLAN.md). Existing kinds (`cell.commit`, `file.create`, `cell.validate`, `cell.unvalidate`) are absorbed: `cell.commit` becomes `cell.created` / `cell.updated`; `file.create` becomes `library.linked` + `source.imported`; validation events become `cell.status_changed`. |
| `cells` | **Reshape, don't drop.** | Add address, scope_id, kind, source_text, source_text_hash, source_version_id, translation_text, tag_dictionary, status, approved_at_version, locked_by_user_id, version, last_edited_*, seq, org_id, source_lang, target_lang, format_meta. Drop columns specific to the old model (e.g. validated-flag column, if it duplicates status). |
| `cells_fts` | **Reshape.** | Re-create FTS5 virtual over `cells.source_text` and `cells.translation_text`. Drop the old triggers, write new ones. |
| `files` | **Decide and document.** | Currently a per-file rollup (cell_count, approved_count, word_count). The new model uses `scope_id` on `cells` instead of a separate file aggregate. Two options: (a) drop `files` and compute rollups via index scans on `cells`; (b) keep `files` as a denormalized rollup keyed by `scope_id` and rename. Recommend (a) for now — re-introduce a rollup table only if scope-level aggregate queries become hot. |
| `checkpoints` | **Drop.** | Subsumed by `snapshots/{project_id}/{seq}.jsonl.gz` in R2 + `projects.snapshot_seq`/`snapshot_key`. The named-snapshot UX, if needed, can be re-implemented on top of the new snapshot blobs without a dedicated table. |
| `cell_validators` | **Reshape into `cell_qa`.** | Migrate the validator framework to the `cell_qa` table per [DATA_PERSISTENCE_PLAN.md §4.9](./DATA_PERSISTENCE_PLAN.md). Existing validators (LQA hot-tier, rule violations, composite cell health) plug into the new shape. |

### 4.3 Migration vs. wipe

Because there are no production users:

- **Wipe `codex-db` outright** is acceptable. Re-create with the new schema. Re-import seed fixtures (eBible corpus importer + a couple of dev projects).
- **In-place migrate** is also acceptable but offers no benefit at this stage. Skip the complexity.

Pick wipe-and-recreate. Document the new migration files under the existing migration tooling (`wrangler d1 migrations create …`).

## 5. Server code (codex-sync-worker)

Located in `sync-worker/`. The current Worker hosts one Durable Object per file with the Y.Doc held in memory.

### 5.1 Delete

| Path / concept | Reason |
|---|---|
| `FileSync.onLoad` Y.Doc construction from `snapshot.bin` + `tail/*.bin` | New system has no per-file Y.Doc. |
| `onSave` debounce + tail write to R2 | Replaced by mutation handler in `frontier-server` writing to D1. |
| Snapshot compaction alarm + background compaction | Replaced by scheduled snapshot rollup writing JSONL to R2. |
| `__apply-event` hot-apply hook | Replaced by DO change broadcast over WS. |
| Hydration cold-start replay | Replaced by snapshot endpoint + `/changes?since=N`. |
| Per-cell fingerprint dedup logic in `onSave` projection | Server-side mutations are version-checked, not deduped. |

### 5.2 Reshape

The Worker becomes a thinner relay:

- One Durable Object per *project* (not per file). Class renames from `FileSync` to `ProjectSync` (or similar).
- DO state is in-RAM presence + ephemeral Y.Text instances for actively co-edited cells. No persisted state.
- `onConnect`: same JWT verification flow; trust headers from `frontier-server`-minted token.
- Add `broadcast({seq, changes, events})` RPC entrypoint called by `frontier-server` after mutation commit.
- Add Y.Text relay machinery (spin up on second-focus, tear down on quiesce, flush via mutation API).

### 5.3 Keep

- JWT verification flow (`onBeforeConnect`, `X-Codex-Role` trust pattern).
- WebSocket lifecycle (hibernate after idle, reconnect handling).
- Admin endpoint pattern, repurposed for snapshot rollup triggering.

## 6. Server code (frontier-server)

Located in `~/frontierrnd/frontier-server/cloudflare/`. **Do not fork.** Extend in place per project memory `frontier-server is PR flow`.

### 6.1 Add

- `POST /projects/:id/cells/:cell_id` — version-checked cell write. Single transaction: append `events` row, upsert `cells`, append `cell_revisions`, increment `projects.sync_seq`, optionally append `commits`. Then RPC into project DO to broadcast.
- `POST /projects/:id/cells/:cell_id/status` — status transition; same transactional pattern.
- `GET /projects/:id/snapshot` — redirect to R2 signed URL; trigger rollup if stale.
- `GET /projects/:id/changes?since=N&limit=M` — JSONL stream of events + cell projections + commits, ordered by `seq`.
- `POST /library/documents` — multipart upload of new library doc; kicks off parse job.
- `POST /projects/:id/library/rebind` — re-parse flow trigger.
- `POST /projects/:id/exports` — export job trigger.
- Format-adapter modules (USFM first, then Markdown, SRT, IDML).
- Snapshot rollup background job.

### 6.2 Keep

- Auth flow (Frontier JWT → role check → mint sync-token).
- `/sync-token` endpoint. Adjust claims if needed; payload becomes `{userId, projectId, role, aud: "sync"}` (file-scoped claim no longer needed since DOs are per-project).
- GitLab permission resolution path (still needed even as GitLab moves library-level).

### 6.3 Reshape

- `POST /events` (current bulk-import endpoint): align its event kinds with the new vocabulary. Bulk import becomes a sequence of `import.started` → many `cell.created` → `import.completed`. Keep idempotency-by-event-id.

## 7. Client code (codex-web-app)

The biggest surface area. Roughly: anything that touches Y.Doc as a primary data source needs reshaping.

### 7.1 Delete

| Path / concept | Reason |
|---|---|
| Full-project Y.Doc hydration in `useFileSync` | Local store is SQLite, not Y.Doc. |
| `bootstrap.ts` share-link path through legacy `signaling/` worker | Replaced by sync-token flow for share-link users. |
| Y.IndexedDB persistence for the per-file Y.Doc | Local persistence is SQLite-WASM (OPFS). |
| React Query caches duplicating Y.Doc state for `original`, `originalHtml`, `context`, etc. | Read straight from SQLite via the local query layer. |
| `FileSync.onLoad`-equivalent client-side replay code | No longer needed; snapshot endpoint loads in bulk. |

### 7.2 Reshape

| Hook / module | New role |
|---|---|
| `useFileSync` (or successor) | Subscribe to project DO over WS. Receive change broadcasts. Apply to local SQLite. |
| `useFileSource` (Phase 4f) | Read directly from local SQLite `cells` table; can be folded into a more general `useCells` hook. |
| `useCells` | Read from local SQLite via reactive query layer (TanStack Query against SQLite, or hand-rolled subscription). |
| Editor write path | Optimistic local SQLite write + outbox enqueue. Replace direct Y.Doc mutations. |
| Co-edit / live cursor | Subscribe to ephemeral Y.Text via DO when this cell is focused and another participant is too; tear down on blur. |
| Status indicator (`SyncStatusIndicator`) | Keep the 5-state model; map to outbox-drain status + WS connection. |

### 7.3 Add

| Module | Purpose |
|---|---|
| `lib/local-store/` | SQLite-WASM bootstrap, schema migrations on the client, query helpers. |
| `lib/sync-engine/` | Snapshot fetch, change replay, last_seq tracking, WS subscribe. |
| `lib/outbox/` | Mutation enqueue, drain loop, conflict surfacing. |
| `lib/y-text-session/` | Per-cell ephemeral Y.Text manager. Spin up on dual-focus, tear down on quiesce. |
| `lib/format-adapters/` (client mirror) | Adapter-aware editor rendering for placeholder tokens (chip rendering, drag-to-reorder). |

### 7.4 Tests

- E2E specs under `e2e/specs/` mostly stay; selectors and data-attributes carry forward.
- Unit tests for sync internals (`src/lib/sync/*.test.ts`) need rewriting against the new sync engine.
- The `y-partyserver-spike.test.ts` round-trip test is obsolete in its current shape; replace with a snapshot+changes round-trip test.

## 10. Order of operations

To avoid a half-broken state, follow this order:

1. **Land schema migrations** (new tables + new columns). Existing reads continue to work because old code paths ignore new columns.
2. **Implement USFM adapter + import pipeline.** Validate against eBible fixtures. CI gate.
3. **Snapshot endpoint + changes endpoint.** Server-side only — no client consumes them yet.
4. **Client SQLite-WASM bootstrap + sync engine.** Read-only initially: local store hydrates, but editor still uses Y.Doc as primary. This is the "two systems running side by side" phase. Verify snapshot round-trip locally.
5. **Switch editor reads to local SQLite.** Y.Doc still exists but is no longer the read source.
6. **Switch editor writes to outbox + version-checked mutations.** Y.Doc no longer mutated.
7. **Reshape DO** to project-scoped, presence + broadcast only. Y.Text relay added for focused co-edit.
8. **Delete legacy code paths** per §5.1 and §7.1.
9. **Wipe legacy R2 keys** per §3.1.
10. **Wipe and re-migrate `codex-db`** per §4.3.
11. **Delete `signaling/`** per §8.

Each step except 9–11 is reversible. 9–11 commit the cleanup; do them last and only after the smoke suite passes on the new architecture.

## 11. Verification checklist

Before declaring cleanup complete, every box must be checked:

- [ ] No production code path reads `projects/*/files/*/snapshot.bin` or `tail/*.bin`.
- [ ] No production code path reads `cell_validators` table; QA framework reads `cell_qa`.
- [ ] No production code path reads `checkpoints` table.
- [ ] `grep -r "signaling" src/ sync-worker/` returns no live code references.
- [ ] `grep -r "snapshot.bin\|tail/" src/ sync-worker/` returns no live references.
- [ ] All E2E smoke specs pass against the new sync stack (`npm run test:e2e:smoke`).
- [ ] Round-trip CI fixture for at least one format adapter is green.
- [ ] Tab memory p99 is below the agreed threshold for a Bible-sized project (target: <500 MB) on a clean session. (See [DATA_PERSISTENCE_PLAN.md §12](./DATA_PERSISTENCE_PLAN.md) on telemetry.)
- [ ] [SYNC.md](./SYNC.md) is updated to point at the new architecture (or marked superseded with a redirect to [DATA_PERSISTENCE_PLAN.md](./DATA_PERSISTENCE_PLAN.md)).
- [ ] [CQRS_LEGACY_IMPORT.md](./CQRS_LEGACY_IMPORT.md) is updated: keep the import-via-events pattern documentation; remove the hydration section since hydration no longer exists.
