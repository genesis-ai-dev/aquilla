# Next-word chain weighting of the source mix — tuning on dev (never the test split)

Generated by `pnpm bia:tune-chains`. A project of size N indexes its first N training pairs and is scored on
the next 250 training pairs (600 next-word positions); low-resource pairs only. Mean top-1 % over pairs.
`s` = chainScale, `a` = sourceWeight (α). Sorted by the mean over every size.

The "e2e journey" column replays the four ghost-text journey checks (`e2e/specs/editor/ghost-text.spec.ts`) on its
30-verse Genesis 1 fixture offline: "la tierra", "su género", an empty cell's "bendijo…", and the source-only key term
"Fructificad". A default must pass all four. **Chosen: `target-stage soft-sum s=300 a=1`** — the best mean among the
variants that pass (the chains weight only the target-side BIA vote; the source is mixed in at α = 1; the bigram
factor then weights the mix). Variants that weight the MIXED score by the chains score as well or slightly better on
dev but fail the key-term check: they floor any word only the source proposes. Best passing variants:

## Where the source starts to beat plain BIA (dev, finer sizes)

Same dev setup, low-resource pairs, mean top-1 %. The crossover is noisy and sits around 150–250 pairs. A gate there
(plain BIA below it) would raise the young-project average, but it would also stop source key terms and an empty
cell's first word from surfacing in projects under the gate — the ghost-text journey's 30-verse project among them.
The default is therefore not gated; see bia-head-to-head.md.
