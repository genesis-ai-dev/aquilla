# Agent API v1.1 — token UI, full command surface, commit idempotency

**Date:** 2026-07-17 · **Status:** approved design · **Tracks:** AQU-533 follow-on
**Prior art:** `docs/AGENT-API.md` (design spec v2), `docs/api/agent-api.md` (implemented surface v1)

## Goal

Complete the v1 command surface of the external Agent API and make it usable without
CLI gymnastics:

1. Users mint, scope, and revoke `aqk_` API tokens from their personal settings page.
2. The three remaining spec'd commands work: `CreateProject`, `UpdateProjectSettings`,
   `LinkMedia` (with audio artifact upload).
3. A latent commit-idempotency hole in the shipped API is fixed (prepare-time event ids).
4. External writes remain **free of AI credit charges** — external agents bring their own
   models; Aquilla incurs no LLM cost — and this is enforced by a regression test.

### Non-goals (deferred, unchanged from v1 spec)

- `run_checks`, jobs/`get_job`, `prepare_export`/`get_export` — future slice; when built,
  Cloudflare Workflows is the intended engine behind it (see §6).
- OAuth 2.1 / MCP connector-directory listing (PAT-only stands).
- Rate limiting (code stays reserved, unenforced).
- Signed upload/download URLs (bytes stay worker-proxied).
- Any new audit ledger tables (`agent_runs` stays internal-agent-only; changeset receipts
  are the external ledger).

## Architecture decision

**All three new commands flow through the existing changeset engine**
(prepare → optional human approval → commit) in `sync-worker/src/external/`.

`CreateProject` and `UpdateProjectSettings` are **receipt-only** commands (spec decision
D8): their apply step is a plain row write, not events. Because sync-worker and
auth-worker share one database and already cooperate via `db/shared/*` modules (e.g.
`db/shared/api-credentials`), the apply logic is extracted into a new
**`db/shared/projects.ts`** called by both workers — auth-worker's internal routes are
refactored onto the same module so there is no forked logic. No service binding, no
cross-worker HTTP.

`LinkMedia` is **event-native**: it compiles to `cell.audio.attach` (+
`cell.audio.select`) events routed through the existing token-bridge → `/events`
perimeter, exactly like `SetTranslation`.

Rejected alternatives: (B) project-lifecycle ops as separate auth-worker REST routes —
splits the API into two styles and loses ask-mode approval on project ops; (C) internal
HTTP bridge sync-worker → auth-worker — a new internal auth scheme plus network failure
modes mid-commit, for two row writes.

## 1. Token UI — Preferences → Account → "API tokens"

**Backend exists** (`auth-worker/src/routes/credentials.ts`); this is UI + client only.

- New entry in `PREFERENCE_SECTIONS` (`src/pages/Preferences.tsx`): slug `api-tokens`,
  group **Account**, icon key-shaped (lucide `KeyRound`).
- New component `src/components/settings/ApiTokensSection.tsx`, following the
  `UsageSection` fetch-render pattern inside `<Section>`.
- New typed client `src/lib/sync/credentials.ts` mirroring `src/lib/sync/usage.ts`
  (`AUTH_BASE` + `Authorization: Bearer <session JWT>`, `fetchWithTimeout`):
  `listCredentials(jwt)`, `mintCredential(jwt, body)`, `revokeCredential(jwt, id)` over
  `GET/POST /api/v2/credentials`, `DELETE /api/v2/credentials/:id`.

**List view:** one row per credential — token prefix, mode badge (`ask`/`act`), scope
(org / project names resolved via existing org/project data), expiry, revoked state.
Revoke = confirm dialog → DELETE (server is idempotent).

**Mint dialog:** mode picker (ask/act) → org select → project select → optional expiry
(presets 30d / 90d / none → `expiresAt`). The dialog filters choices to what the
caller's roles permit — scoping requires ≥CONTRIBUTOR in the target; **act mode requires
≥MAINTAINER and a project scope** (the dialog disables act until a project is chosen).
Client-side filtering is UX; the server 403 remains the authority.

**Show-once:** the plaintext `aqk_…` token renders exactly once in the post-mint dialog
with a copy button and an explicit "you won't see this again" notice. It is never stored
client-side; the list shows only `tokenPrefix`.

## 2. Commands

Additions to the `Command` union in `sync-worker/src/external/commands.ts`, each with a
validation branch and a required-role mapping, flowing through
`prepare.ts` → `commit.ts`.

| Command | Payload | Role gate | Precondition at prepare | Commit path |
|---|---|---|---|---|
| `CreateProject` | `{ projectId?, name, orgId? }` | org role ≥ MAINTAINER (org-level check — no project exists yet) | `projectId` (if given) not taken | receipt-only via `db/shared/projects.ts` (`ON CONFLICT DO NOTHING` + creator membership level 700) |
| `UpdateProjectSettings` | `{ projectId, settings, ifMatchVersion }` | project role ≥ MAINTAINER | stored settings `version === ifMatchVersion`, else `plan_stale` | receipt-only via shared module; version-guarded `UPDATE … WHERE version = ?`; if the validation threshold changed, run the re-projection statements locally (sync-worker owns the projection; auth-worker's copy of this fan-out moves into the shared module) |
| `LinkMedia` | `{ fileId, cellId, artifactId }` | per role-policy for `cell.audio.attach` (CONTRIBUTOR) | cell exists in projection; artifact exists, is kind `audio`, same project | compiles to `cell.audio.attach` + `cell.audio.select` events via token-bridge → `/events` |

Notes:

- **`CreateProject` scope rule:** credential must be unscoped or org-scoped to the target
  org; a project-scoped credential cannot create projects. Since act-mode tokens are
  required to be project-scoped at mint, **`CreateProject` is effectively ask-mode only**
  — every agent-initiated project creation passes human approval at `/approve/:id`.
  This is intentional and documented, not incidental.
- **Receipt provenance (D8):** receipt-only commits stamp the receipt with
  `{ credentialId, channel: 'mcp' | 'rest', changesetId, command, appliedAt }` and, for
  CreateProject, the created project id.
- **`CreateProject` role check location:** prepare performs the org-role check directly
  (the existing per-project `REQUIRED_ROLE` path doesn't apply to a not-yet-existing
  project); commit re-checks before applying, mirroring the live-role re-check pattern.

**Shared module `db/shared/projects.ts`:** extracts create-project (from
`auth-worker/src/routes/projects.ts` `POST /` handler: org resolution, insert, creator
membership) and version-guarded settings update (from
`auth-worker/src/routes/project-settings.ts`: normalize, first-write insert vs
`version+1` update, threshold-change detection + projection statements). Auth-worker
routes become thin HTTP shells over the module. Behavior of the internal routes is
unchanged — their existing tests must stay green.

## 3. Audio artifacts

`sync-worker/src/external/artifacts-route.ts` gains `kind: 'audio'`:

- Accepted content types: `audio/wav`, `audio/mpeg` (mp3), `audio/mp4`/`audio/x-m4a`,
  `audio/ogg`. Size cap unchanged (25 MB).
- Stored into the **existing audio R2 key layout** used by `sync-worker/src/audio.ts`, so
  the app's playback routes serve externally-uploaded audio with no special-casing.
- Inspect returns size + content type only. No duration/waveform sniffing in v1 (would
  require decoding; YAGNI).
- Upload remains REST-only. MCP tool descriptions for `LinkMedia` point at the REST
  upload endpoint.

## 4. Commit idempotency — prepare-time ids

**Bug being fixed:** `commit.ts` currently mints event/file/cell UUIDs at commit time
(`uuidv7()` at commit.ts:163, 332–358) and flips the changeset to `committed` only at the
end. A worker eviction mid-commit (a 5,000-cell `PlanImport` is ~50 chunked event posts
in one request) leaves the changeset `staged`; a retry re-mints fresh ids → duplicate
`source.cell.create` events and a duplicate file.

**Fix:**

- `prepare.ts` mints **all** ids (event ids; and for `PlanImport`, the file id and any
  generated cell ids) and stores them in the changeset plan JSON.
- `commit.ts` replays the stored ids. A crash-and-retry re-posts identical event ids and
  the `/events` idempotency layer absorbs the duplicates. Applies to `SetTranslation`,
  `PlanImport`, and `LinkMedia`.
- `commit.ts` sets `status = 'committing'` when it starts applying, and `committed` at
  the end. Commit accepts a changeset in `staged` **or** `committing` (the latter is the
  retry-after-crash case). This also reserves the contract hook a future async/jobs
  commit mode needs (§6).
- Receipt shape is unchanged.

## 5. Attribution & billing guard

- **No AI credits, by construction and by test.** The external path never calls an LLM
  and never calls `recordCredit`. A regression test performs an external commit and
  asserts `org_credit_usage_daily` is untouched. (Internal agent + chat billing via the
  `llm`/`agent` rails is unchanged.)
- **Lightweight attribution, no new tables.** Changeset receipts remain the external
  ledger. Verify that provenance stamps — credential id, channel (`mcp`/`rest`),
  changeset id — land on **every** projected event from external commits (the W4 fix
  covered the MCP channel for existing commands; extend to `LinkMedia` events), and on
  receipt-only receipts per §2.

## 6. Future: jobs surface (context, not scope)

When `run_checks` / export / large-import jobs are built, Cloudflare Workflows is the
intended durable engine (per-step retry, R2 for large outputs, `waitForEvent` for
approvals). Nothing in this slice adopts Workflows; the only accommodations are the
`committing` status (§4) and receipt stability, which let an async commit mode slot in
without breaking callers. Interactive/streaming surfaces (internal agent SSE, chat proxy)
are explicitly not Workflow candidates.

## 8. Error handling

Reuse the existing `ExternalError` codes wherever they fit:

- Settings version drift → `plan_stale` (both at prepare-vs-live re-check and commit).
- Scope violations → `scope_denied`; role failures → `permission_denied`.
- Project id collision at commit (raced between prepare and commit) → `conflict`
  (add the code if not already present in `errors.ts`; check first).
- Artifact wrong kind / wrong project for `LinkMedia` → `invalid_request` at prepare,
  `plan_stale` if it disappears before commit.

## 9. Testing

Per AGENTS.md: sync-worker and auth-worker suites run in their own packages; SPA under
root vitest.

**sync-worker (`cd sync-worker && npm test`):**
- Validate/prepare/commit coverage for all three commands (happy path + each error row).
- New rows in the permission-parity matrix (`external-permission-parity.test.ts`):
  CreateProject (org roles), UpdateProjectSettings (maintainer vs contributor),
  LinkMedia (contributor vs observer).
- **Commit-replay test:** run a commit, simulate mid-commit crash by resetting the
  changeset to `committing` with the partial state, run commit again; assert no
  duplicate events/files and a single receipt.
- Audio artifact upload + inspect + wrong-kind rejection.
- **No-credits regression:** external commit leaves `org_credit_usage_daily` unchanged.

**auth-worker (`cd auth-worker && npm test`):**
- Existing project-create and project-settings route tests stay green over the extracted
  shared module (the refactor is behavior-preserving).

**SPA (root `pnpm test`):**
- `ApiTokensSection`: list render, mint flow (role-filtered org/project options, act
  disabled until project-scoped, show-once token display), revoke confirm.
- `src/lib/sync/credentials.ts` client (request shapes, error propagation).

## 10. Success criteria

1. A user with maintainer role can, entirely in the UI, mint (a) an org-scoped ask
   token with which an agent creates a project via human approval, and (b) a
   project-scoped act token with which the agent uploads audio, attaches it to a cell,
   adjusts a validation threshold, and imports cells — all with provenance-stamped
   receipts/events.
2. Forced mid-commit retry of a `PlanImport` produces zero duplicate events.
3. `org_credit_usage_daily` shows zero deltas from any external API activity.
4. Internal project-create/settings routes behave identically (tests green) after the
   shared-module refactor.
