The suppression count is the floor, not the ceiling. The rule is **structurally blind** to four
classes (documented in `tools/eslint-rules/no-unkeyed-string.cjs` and re-verified here):

1. Template literals **with** expressions — `` `Deleted ${n} files` `` is never flagged, and these
   are exactly the strings that need placeholders and plural categories.
2. Strings in `const` arrays/objects hoisted out of component scope (`const OPTIONS = [{ label: 'Owner' }]`).
3. Everything outside `src/**/*.tsx` — the rule is not applied to `src/**/*.ts` at all, so
   UI-facing strings in `src/lib/**` (toast text, error copy, option tables) are unguarded.
4. Files matched by `IGNORED_FILE_PATTERNS` in `tools/eslint-rules/allowlist.cjs` (admin, legal,
   dev surfaces) — deliberate policy, but the scan must still *report* them so the exemption
   stays a decision rather than a blind spot.

Closing 1–3 is WS-SCAN's job; it is the "scan the entire app" half of the request.

## §2 Operating model

- `claude/unlocalized-ui-strings-scan-ska46i` = delivery branch. Only the orchestrator pushes.
- `swarm/integration` = accumulation branch. Agents branch off its tip into their own worktree.
- **Namespace ownership is exclusive: exactly one agent WRITES each `namespaces/*.ts` file.**
  Any agent may READ and reuse keys from any namespace — reuse is strongly preferred over
  minting a near-duplicate, because `no-duplicates.test.ts` fails on duplicate English strings.
- **Barrels are pre-wired by the orchestrator and forbidden to agents.** `namespaces/index.ts`
  and `messages/en.ts` already import/spread the three new namespaces (`settings`, `agent`,
  `workspace`), so an agent's `t("settings.foo")` typechecks the moment it adds the key. This
  is the deliberate fix for the 9-way barrel conflict the AQU-511 swarm hit.
- **`eslint-suppressions.json` is orchestrator-owned.** Six agents regenerating it is a
  guaranteed conflict; the orchestrator prunes once per merge wave.
- **`source-hashes.json` and `messages/<locale>.ts` are orchestrator-owned.** Translation
  agents emit plain JSON; the orchestrator runs `pnpm i18n:import` serially.

### Forbidden to all subagents

| Forbidden | Why |
| --- | --- |
| `git push`, any remote write | Only the orchestrator delivers. |
| `src/lib/i18n/namespaces/index.ts`, `src/lib/i18n/messages/en.ts` | Pre-wired; editing them re-creates the conflict this design removes. |
| `src/lib/i18n/messages/{th,my,mfa,ar}.ts`, `source-hashes.json` | Generated by `pnpm i18n:import`, orchestrator-run. |
| `src/lib/i18n/namespaces/common.ts` | Shared vocabulary; reuse its keys, never extend it. Need a new shared word? Put it in your own namespace and file a trace. |
| `eslint-suppressions.json` | Orchestrator prunes once per wave. |
| `src/pages/Homepage/`, `src/pages/CaseStudy/`, `src/pages/Beta/`, `src/pages/PrivacyPolicy.tsx` | English-only prerendered marketing; `t()` breaks prerendering. |
| `pnpm test:e2e*`, `pnpm dev`, `scripts/e2e-up.ts`, `pnpm i18n:shots` | One stack per machine; orchestrator runs these serially. |
| Another agent's owned files | Partition is disjoint by construction. |

## §5 The `src/lib/**` design rule (wave 2's central correction)

`docs/swarm/I18N-ORCHESTRATION.md` (the AQU-511 wave) forbade calling `t()` from `src/lib/**`
on the grounds that it is a hook, and declared the whole area out of scope. **That note is
stale**: `src/lib/i18n/standalone.ts` post-dates it and exists precisely for non-React modules.
The 160 `non-tsx` findings are the largest actionable class in the scan, so the area is back in
scope — under a rule that is not optional:

| Shape | Correct pattern | Why the other one is a BUG |
| --- | --- | --- |
| Module-scope `const` table (`GEMINI_TTS_VOICES`, `BUILTIN_CHECKS`, `brief/schema.ts` fields, Preferences option tables) | Store a `MessageKey` in the data; resolve with `t(row.labelKey)` at the render site | `standalone.t()` reads the locale **at call time**. Called at module scope it runs once at import and freezes that locale forever — the app looks translated until the user switches language, then silently doesn't. |
| Function called per render/event (`ai-error.ts`'s categorizer, `permissions/denial.ts`) | `import { t } from "@/lib/i18n/standalone"` | Fine here: the value is recomputed per call. Its documented limitation (no re-render on locale change) only bites values computed once. |

When in doubt: keys-in-data is always correct, just more plumbing.
