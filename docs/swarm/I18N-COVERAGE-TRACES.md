## Detector blind spots (WS-SCAN owns closing these)

- [DONE] (tmpl-expr) Template literals with expressions are never flagged by
  `i18n/no-unkeyed-string`. These are the strings that most need catalog placeholders and
  plural categories, so the hole is substantive, not cosmetic. —
  `tools/eslint-rules/no-unkeyed-string.cjs`. **Closed by WS-SCAN**: `scripts/i18n-scan.ts`
  detects these via positive UI-position evidence (notification call / translatable JSX
  attribute-or-child / translatable object property), with the static (expression-dropped)
  quasis run through `isAllowedString` first to avoid the `` `${label}:` `` false positive the
  rule's own header calls out. 82 findings, all `key-it`. See `docs/swarm/I18N-COVERAGE-SCAN.md`.
- [DONE] (hoisted-const) Strings in `const` arrays/objects outside component scope are
  invisible to the rule (no data-flow analysis). — same file. **Closed by WS-SCAN**: walks
  module-scope (depth-0) `const` declarations into nested arrays/objects; `label`-shaped
  properties are reported at any nesting depth, flat vocabulary maps
  (`STATUS_LABELS`/`Record<K,string>`) only at the direct-initializer level (this restriction
  was added after an early scanner pass wrongly flagged `id`/`ext`/`badge` discriminator keys
  inside option-array items). 97 findings, all `key-it`. See scan doc.
- [DONE] (non-tsx) The rule is scoped to `src/**/*.tsx`; UI-facing strings in `src/**/*.ts`
  (`src/lib/**` toast/error/option tables) are entirely unguarded. — `eslint.config.js`.
  **Closed by WS-SCAN**: 160 findings after excluding `src/lib/i18n/{messages,namespaces}/**`
  (the i18n catalog itself — its strings are either already-keyed source text or translator
  context notes, not unlocalized UI copy; see scan doc "shape of the problem" section for the
  621-finding false-positive this exclusion removed). Concentrated in `src/lib/audio`,
  `src/lib/brief`, `src/lib/qa`, `src/lib/lqa`. All `key-it`.
- [DONE] (ignored-files) `IGNORED_FILE_PATTERNS` exempts admin/legal/dev surfaces by policy.
  The scan must still enumerate them so the exemption stays an auditable decision. —
  `tools/eslint-rules/allowlist.cjs`. **Closed by WS-SCAN**: 232 findings (157
  `exempt-admin-dev`, 75 `exempt-legal`, 0 `exempt-showcase` — no `showcase/` dir currently
  exists under `src/`), generated by re-running the real rule's own JSXText/JSXAttribute/
  notification-call detectors against files the rule itself skips. Full list in scan doc
  appendix, class 4.

### New blind spots found while closing the above (not yet assigned an owner)

- [OPEN] (in-body-object) A 5th blind spot, structurally adjacent to `hoisted-const` but not
  covered by any of the four classes in this workstream's brief: a `label`-shaped object
  literal built *inside* a component's render body (not a module-scope `const`) and passed
  down via `<Child {...config} />` prop-spreading is invisible to every detector here — it
  isn't `JSXText`/`JSXAttribute` (the real rule's job), isn't hoisted (not module-scope), and
  if the file is `.tsx` it isn't `non-tsx` either. Not scanned; no count available. Needs a
  data-flow-aware detector (track spread-into-JSX) or a manual sweep. —
  `docs/swarm/I18N-COVERAGE-SCAN.md` § "What this scanner still cannot see"

## Known hazards for any agent in this repo

- [OPEN] (git-stash-shared) **`git stash` is NOT worktree-local.** `refs/stash` is shared
  across every worktree backed by the same `.git` dir, so with N concurrent swarm agents a
  `git stash pop` can return ANOTHER agent's stash. WS-E hit this against WS-C mid-task and
  recovered only by locating its own unreachable stash commit via `git fsck --unreachable` and
  matching it by file list. **Do not use `git stash` in a swarm worktree** — commit a WIP
  instead, or use `git worktree`-local checkouts.
- [OPEN] (case-fold-copy-drift) `no-duplicates.test.ts` case-folds before comparing (deliberate:
  three of the four target locales have no letter case, so a case-only split is pure duplicate
  work). Resolving a collision therefore sometimes means **changing visible English copy** to
  match an existing key. Landed instances: "Project info"→"Project Info", "Draft context"→
  "Draft Context", "Terminology library"→"Terminology Library", "Project Lead"→"Project lead",
  "Downloading"→"downloading" (WS-B); "Create Translation Rule"/"Rule Name"/"Create Rule"→
  sentence case (WS-E); `ProposalReceipt` "done"→"Done" (WS-D). Each is defensible individually;
  collectively they are unreviewed copy drift and deserve a human read-through.
  WS-F added more: `nedLabel.light` renders **"slight"** (collided with
  `onboarding.preferences.theme.light`), the create-project trigger became **"New Project"**
  (was "New project", to reuse `projectSettings.create.trigger`; 7 assertions updated with it),
  and three "Back to dashboard" buttons were unified onto one casing.
