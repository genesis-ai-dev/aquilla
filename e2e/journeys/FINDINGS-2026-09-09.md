# Second pass: the keep-list as stories, 2026-09-09

Overnight after the first run. Goal: turn the rest of the smoke keep-list
into stories, prove each with a cold agent run, write its replay, and earn a
five-run streak per story. Same stack, same branch, agent-browser 0.27.0.

## How it was done, and what broke

Three agents worked in parallel by area (projects and orgs, editor, two-user
collab), each driving its own agent-browser sessions against the one local
stack. Twenty stories and twenty replays came out of it. Two things broke:

1. **The stack fell over under the combined load.** With three agents, one
   of them running its own sub-agents, the sync worker's wrangler process
   exited with a blank `ERROR` and the dev-stack script shut everything down.
   Every streak line from that window is a FAIL with a note such as
   `import preview`, `login`, or `New Project button`. Those are not app
   failures and not harness failures; the app was gone. The calibration pass
   below reran every story one at a time on a fresh stack.
2. **The agents ran out of account budget mid-task.** Their reports never
   arrived. The stories, replays, and streak lines on disk are the record.

The sync worker died a second time during the serial calibration pass, in
the middle of the back-translation story with nothing else running. The
wrangler log names the cause both times: workerd reports
`disconnected: ::write(...): Connection reset by peer`, then wrangler's
ProxyController raises `Network connection lost.` and `wrangler dev` exits
with code 1, which makes the dev-stack script shut the whole stack down. A
browser session closing while its project-sync socket is still open is
enough. This is wrangler 4.120.0 behaviour, not app code; 4.130.0 is out
and worth trying. Every `FAIL: login` in `streaks.tsv` that took under
five seconds is this: Vite was gone, so the dev-login page refused the
connection.

Lessons for the scheduled run: one story at a time per stack, parallelism
only across stacks (the shard ports the e2e harness already uses), and a
supervisor that restarts the stack and retries the story when the workers
exit. The streak runner now waits for the stack before each round.

## What the agents found in the app

Things worth a human look. None of them blocked a journey.

- **Org-level Add a member is Owner-only.** At Dev Org, alice is a
  Maintainer and sees only **Add to projects**, whose dialog says
  "org-wide membership is unchanged." The smoke spec seeds an Owner; the
  story now says so. Whether Maintainers should be able to add org members
  is a product question.
- **Add in the member dialog enables on the typed username alone.** Picking
  the `bob` suggestion checkbox is optional, and clicking it right before
  **Add** can race the re-render so that no request is sent. A user who
  types fast can lose the add silently.
- **The cell action rail hides itself about 2.2 seconds after a hover**,
  even when the pointer stays on the row (`useRailIdleHide`). A person
  reading the rail before clicking **Add comment** can watch it vanish.
  **Open cell details** pins the same actions without hover.
- **The Comments page has no live subscription.** It fetches once on load
  and offers a **Refresh** button. A comment written by another user drains
  through a five-second server-side outbox, so a reader who opens the page
  within seconds of the write sees nothing until they refresh.
- **The rule row's trash-can button has no accessible name.** A screen
  reader and an agent both see an unlabeled button. The rule name sits in
  the parent `<li>` as plain text.
- **Sidebar links miss `find role link --name`.** Consistent across the app
  (org sidebar, **Project settings**, **General**, the Preferences dialog's
  **Workspace** link). The snapshot lists them; the locator does not find
  them. Likely an icon-plus-text pattern in the link; worth a look at how
  the accessible name is computed, since it may also affect assistive tech.
- **`/project/<id>/rules` redirects to `/project/<id>/memory/quality`.**
  Expected, but every agent tripped on it once; the stories now say so.
- **Right after reload, Project Settings shows Source Language empty** for a
  beat while the label rehydrates from the code. The smoke spec avoids
  checking that field after reload for the same reason.
- **The local mock LLM answers back-translation requests** with
  "I'm running in deterministic local mode..." and a "Matches this
  translation" badge, so the reviewer-lock story works locally without the
  Playwright per-test override.

## Harness notes added today

- `find role button --name "Account menu: alice"` misses; dropping the
  colon and the rest (`--name "Account menu"`) finds it.
- Popovers and dialogs portal outside the row. Scope snapshots to `main` or
  `body` to see them; `-i` hides non-interactive nodes such as a
  `dialog "1 online"` or a posted comment. Use `get text` for plain text.
- Typing a run of spaces through `type` loses the doubling in ProseMirror;
  `keyboard inserttext` sends one input event and keeps it.
- Snapshot refs on the Rules list go stale on almost every action; re-query
  by role at click time instead.
- `wait --text` never matches a placeholder. Wait for the element.

## Where this goes next

Decided on the 2026-09-09 calls. Cloudflare no longer runs tests; it builds
a full-stack preview per branch (AQU-1036, merged to dev the same day).
Bots QA each pull request against its preview and leave a comment; humans
sanity-check dev before main; approved PRs should deploy without queueing.
`PR-BOT.md` is that flow written as steps an agent can follow. This
folder's part in it:

1. The stories are the per-story bot briefs. Each PR's diff picks which
   ones run.
2. The replays are the free, fast first pass. A cold walk follows only
   where a replay fails or where the PR's own claim has no story yet.
3. `AQUILLA_BASE`, `AQUILLA_ORG_ID`, and the QA-account login in
   `replays/_lib.sh` point everything at a preview instead of a laptop.
   Untested against a real preview at the time of writing: the preview
   workers had just landed on dev and no QA account exists on development
   storage yet.
4. The local stack keeps two jobs: writing new stories and calibrating
   them. The stack-crash lessons above apply there, not to previews.

Still open: which runtime hosts the bots (Grokbot, Codex with Astra, or a
Claude Code routine with agent-browser), a QA account on development
storage, and the PR comment format the team wants to read.
